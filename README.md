## Why I Built This

After researching SKIMS publicly — product launches, customer reviews, job postings, engineering blogs, and the Fivetran case study about SKIMS' data platform — I identified three problems the Data, Insights & Loyalty team is likely working on right now:

**1. Limited drops sell out in minutes, but not evenly across sizes.**
Core sizes vanish instantly while edge sizes linger. The business problem is buy quantity by size, not just total inventory. Waitlist data exists but isn't being used systematically to inform pre-launch buy decisions.

**2. Returns are a fit problem, not a product problem.**
Public reviews consistently cite sizing confusion as the primary reason for returns. "Too small" accounts for the majority of fit-related returns, concentrated in specific size and category combinations. This is fixable with better size guidance, not product redesign.

**3. The MARBLE/ONYX rewards program is brand new and needs analytical infrastructure.**
Launched in 2024, the two-tier program offers three paths to ONYX status. Which path produces the highest-LTV customer? Where do MARBLE members stall? What is the single best next action per segment? These are exactly the questions a founding loyalty analyst would be answering in their first 60 days.

Instead of writing a cover letter describing how I would approach these problems, I built the analysis.

## The Data

All data is 100% synthetic, generated by a [Python script](data_generation/generate_data.py) designed to mirror realistic DTC apparel behavior. No real SKIMS data was used.

**Scale:**

| Table | Rows |
|---|---|
| Customers | 50,000 |
| Products | 500 |
| Orders | 250,000 |
| Order Items | ~600,000 |
| Waitlist Signups | 75,000 |
| Engagement Events | 400,000 |
| Marketing Touches | 600,000 |

**Patterns baked into the data to mirror real-world DTC behavior:**

- ONYX-tier customers order 4x more frequently than non-rewards customers
- Sculpt and Swim categories have 2x the return rate of Soft Lounge
- XXS and XS sizes return at 2x the rate of M and L
- 80% of waitlist signups concentrate in the 72 hours before a drop launch
- 35% of all returns cite "too small" as the reason

These patterns are intentional. They make the analysis realistic and the insights credible even on synthetic data.

## Key Findings

### Drop Demand Forecast
- 72-hour pre-launch waitlist signups are a stronger predictor of demand than total waitlist size
- A gradient boosting model explains demand variation with predictions within a small margin on average
- M and L are consistently the highest-demand sizes; XXS and 4X have low waitlist signals but high return rates, suggesting size guide issues rather than low demand

### Rewards Program Analysis
- ONYX members generate significantly higher net revenue than non-rewards customers
- The majority of MARBLE members are in "early stage" with no clear momentum toward ONYX
- Four distinct MARBLE segments exist: High Spenders, Brand Evangelists, Casual Shoppers, and Dormant Members, each requiring a different intervention
- 90-day retention is materially higher for rewards members vs non-rewards customers

### Returns Analysis
- Fit-related returns (too small + too large) account for the majority of all returns
- XXS and XS return at nearly double the rate of M and L
- 15 specific SKUs account for a disproportionate share of returned revenue
- A proposed A/B test (enhanced size guide callout on high-return PDPs) is fully designed with sample size calculations, primary/secondary metrics, guardrails, and rollout plan

## Running This Project Locally

### Prerequisites
- Python 3.11+
- A Snowflake account (free 30-day trial available at snowflake.com)
- dbt Core with the Snowflake adapter

### Setup

**1. Clone the repo**
```bash
git clone https://github.com/prathikshaurs/skims-drop-intelligence.git
cd skims-drop-intelligence
```

**2. Create a virtual environment and install dependencies**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**3. Generate the synthetic data**
```bash
python data_generation/generate_data.py
```

**4. Set up Snowflake**

Create a Snowflake account, then run the SQL in `sql/setup/01_create_tables.sql` to create the database, schema, and tables. Load the generated CSVs from `data/raw/` using Snowflake's Load Data wizard.

**5. Configure dbt**

Create `~/.dbt/profiles.yml` with your Snowflake credentials:
```yaml
skims_dna:
  outputs:
    dev:
      type: snowflake
      account: YOUR_ACCOUNT
      user: YOUR_USER
      password: YOUR_PASSWORD
      role: ACCOUNTADMIN
      warehouse: COMPUTE_WH
      database: SKIMS_DROP_INTELLIGENCE
      schema: DBT_DEV
      threads: 4
  target: dev
```

Run dbt:
```bash
cd dbt_project/skims_dna
dbt run
```

**6. Configure and run the Streamlit dashboard**

Create `.streamlit/secrets.toml` in the project root:
```toml
[snowflake]
account = "YOUR_ACCOUNT"
user = "YOUR_USER"
password = "YOUR_PASSWORD"
database = "SKIMS_DROP_INTELLIGENCE"
warehouse = "COMPUTE_WH"
role = "ACCOUNTADMIN"
```

Run the dashboard:
```bash
streamlit run dashboard/app.py
```

**7. Run the analysis notebooks**

Open VS Code, navigate to the `analyses/` folder, and run each notebook with the `.venv` kernel selected.
